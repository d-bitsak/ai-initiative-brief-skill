# Навык «Бриф на ИИ-инициативу»

Навык для Claude, который превращает транскрипт интервью с заказчиком (discovery / CustDev / установочная встреча) в заполненный **Бриф на ИИ-инициативу** — Word-документ по канонической структуре из 12 разделов.

Навык не выдумывает содержание. В бриф попадает только то, что заказчик реально сказал; всё остальное собирается в один список уточняющих вопросов, задаётся в чат за один проход и достраивается после ответов.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `SKILL.md` | Инструкция навыка: рабочий процесс, принципы разбора, карта соответствия разделов и типичные ошибки |
| `assets/template.md` | Канонический пустой шаблон брифа — источник истины по структуре |
| `assets/example_filled.md` | Заполненный пример (ИИ-помощник дизайнера) — образец стиля и детализации |
| `scripts/read_transcript.py` | Извлекает текст из транскрипта (.docx / .txt / .md, при наличии библиотек — .pdf) |
| `scripts/build_brief.py` | Собирает .docx из заполненного markdown, сохраняя курсивные подсказки шаблона |
| `examples/kp-assistant/` | Сквозной пример: транскрипт интервью → собранный бриф → готовый .docx |
| `ai-initiative-brief.skill` | Тот же навык, упакованный для загрузки в приложение Claude |

## Структура брифа

12 разделов, порядок и формулировки заголовков менять нельзя. Звёздочкой отмечены обязательные:

1. Название инициативы\*
2. Контекст\*
3. Ваша идея\*
4. Проблемы бизнеса\*
5. Бизнес-цели\*
6. Job Story (опционально)
7. Критерии успеха
8. Измеримые цели
9. Ограничения и доп. требования
10. Источники данных и знаний
11. Сроки — дата начала, дата MVP, дата масштабирования
12. Проектная группа — владелец портфеля (ВПП), заказчик, аналитик, разработчик, другие участники

## Установка

### Claude Code

Клонировать в папку пользовательских навыков:

```bash
git clone https://github.com/d-bitsak/ai-initiative-brief-skill.git ~/.claude/skills/ai-initiative-brief
```

Навык подхватится при следующем запуске сессии. Чтобы навык был доступен только в одном проекте, клонируйте его в `.claude/skills/ai-initiative-brief` внутри этого проекта.

Обновление до свежей версии:

```bash
git -C ~/.claude/skills/ai-initiative-brief pull
```

### Приложение Claude (десктоп / claude.ai)

Скачайте `ai-initiative-brief.skill` и загрузите его в настройках навыков: Settings → Capabilities → Skills → Upload skill. Если навык уже установлен, удалите старую версию перед загрузкой новой, иначе получится дубль.

## Как пользоваться

1. Положите транскрипт интервью (.docx / .pdf / .txt / .md) в папку проекта.
2. Попросите Claude собрать бриф — например: «Собери бриф на ИИ-инициативу по транскрипту интервью из этой папки».
3. Ответьте на список уточняющих вопросов. Чаще всего спрашивают то, что почти никогда не звучит в интервью: SMART-цифры, три даты из раздела «Сроки», ФИО и роли проектной группы, технические ограничения и доступы.
4. Заберите готовый .docx — он сохраняется в папку проекта.

Ненужные разделы можно пропустить: в ответ на вопрос достаточно написать «пропустить». Поля, которые остались без ответа, попадут в документ с видимой пометкой «требует уточнения», а не будут заполнены правдоподобной выдумкой.

Скрипты можно запускать и вручную:

```bash
python3 scripts/read_transcript.py "интервью.docx"
```

```bash
python3 scripts/build_brief.py brief_filled.md "Бриф на ИИ-инициативу — Название.docx"
```

Для сборки .docx нужен `python-docx`:

```bash
pip install python-docx --break-system-packages
```

## Принципы, на которых держится навык

- **Только факты из транскрипта.** Если заказчик не сформулировал вывод сам — навык не вкладывает ему в уста аккуратную формулировку.
- **Боль ≠ пожелание.** «Проблемы бизнеса» — это наблюдаемый негативный эффект («долго», «ошибаются», «теряем сделки»), а не отсутствие фичи. Фичи и хотелки идут в «Идею» и Job Story.
- **Цифры и даты — только названные.** Ни метрики, ни сроки не выводятся из общих фраз и не считаются от даты интервью.
- **Курсивные подсказки остаются в документе.** Под каждым заголовком в .docx сохраняется памятка из шаблона — так бриф остаётся понятным тому, кто будет его дозаполнять.
